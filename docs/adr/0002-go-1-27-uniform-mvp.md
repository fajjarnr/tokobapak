# Uniform Go 1.27.0 untuk 9 Service MVP — Hexagonal Lightweight + Saga Choreography

Konteks: 9 service MVP semula polyglot. Kami memutuskan rewrite menjadi Go 1.27.0 seragam dengan **hexagonal lightweight tanpa `outbox-starter`/`saga-starter` PayU** — parity PayU `domain/port/adapter` tapi tanpa library Java. Template: `cmd/server/main.go`, `internal/domain/model + port` (interface), `internal/application/service`, `internal/adapter/{postgres,http,kafka,client/payu}`, `config`, `migrations`, stack `chi/gin, sqlc+pgx, kafka-go, go-redis, go-elasticsearch, golang-jwt`. Event via **outbox manual** (tabel `outbox` + poller `SELECT FOR UPDATE SKIP LOCKED` tiap 5s, topic `tokobapak.<domain>.<event>.v1` + DLQ `.dlq`), Saga **choreography** `OrderCreated → inventory reserve → PayU charge → shipment` kompensasi `OrderCancelled` tanpa orchestrator.

Keputusan ini hard to reverse karena mengganti toolchain dan menambah 1 tabel outbox + poller per service. Surprising karena `ARCHITECTURE.md` v2.0 Technology Agnostic dan PayU pakai `shared/outbox-starter`/`saga-starter` Java — kami pakai manual Go 30 baris. Trade-off: hexagonal via Port interface + exactly-once outbox + Saga tanpa starter (hemat vs PayU) vs boilerplate tambahan + eventual consistency manual; mitigasi via `pgx` + `kafka-go` poller.
